# ADR 0001 - Stack

**Status:** Accepted - {{YYYY-MM-DD}}

## Context

{{APP_NAME}} started from Livingit's starter kit on {{YYYY-MM-DD}}: an app that runs, so
the team could build from the first day. The kit chose the stack below; from that day the code is the team's, and
this record is theirs to change with a new ADR.

## Decision

- Language and framework: TypeScript, SvelteKit 2 and Svelte 5 (runes).
- Runtime and package manager: Bun for local work and scripts; the built app is a plain Node server
  (`@sveltejs/adapter-node`), so it runs wherever the team chooses to host it.
- UI: shadcn-svelte on Tailwind CSS 4, with the theme as CSS variables in `src/app.css`. Texts through Paraglide
  (`messages/`), with {{LANGUAGE}} as the first language.
- Database and schema/migration tool: Postgres, through Drizzle ORM. Migrations are generated by drizzle-kit,
  read before they are committed, and additive only. Postgres runs in Docker for local work (`compose.yaml`).
- Auth: better-auth 1.7.7, installed as its installation guide says: the instance with the Drizzle adapter, the
  SvelteKit handler with the session on `locals`, the client, its tables generated by its CLI, and its secret in
  `.env`. No way to sign in is turned on; the team adds SSO or the plugin the project needs.
- Hosting: {{STACK_HOSTING}}
- CI: GitHub Actions. The PR check on every PR to `main` installs with a frozen lockfile and runs test, lint,
  check and build. Deploy is chosen with the hosting.

## Consequences

- The app has no way in until the team adds one, and nothing about hosting until the team chooses it.
- Tests run in Node without a database: every outside service is behind a module with a fake.
- SvelteKit 3 was out when the kit was made; the kit stayed on 2 because better-auth 1.7.7 names SvelteKit 2 as
  the version it works with (its peer dependency). Revisit when better-auth names 3.
